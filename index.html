Under the hood

Pure SQL, deliberately

Every table hangs off an organization, so one deployment can run many institutions — each with its own departments, programs, and invite-key membership.

  • Hand-written queries via psycopg2, not an ORM's best guess
  • Data access, service logic, and API routes kept in separate layers
  • Multi-tenant from the schema up
Role-based, not role-suggested

Everyone sees exactly their scope

Admins manage structure and people. Faculty run their offerings and mark attendance. Students see their own record — nothing more, enforced server-side.

  • JWT session carries org membership + role
  • Access checked at the query layer, e.g. require_org_admin()
